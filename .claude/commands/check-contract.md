# /check-contract

Verify Spring Cloud Contracts between services.

## Usage

```
/check-contract
/check-contract <producer-service>   # verify a specific producer
```

## Contract locations

```
inventory-service/src/test/resources/contracts/
  reserve-stock.groovy       # HTTP contract: POST /api/inventory/reserve

order-service/src/test/resources/contracts/
  order-confirmed-event.groovy   # Kafka contract: order.confirmed topic
```

## What this command does

### Producer-side verification (inventory-service)

```bash
mvn verify -pl inventory-service -P contract-test --no-transfer-progress
```

Spring Cloud Contract generates tests from Groovy DSL and runs them against the real service.
Pass = the service correctly implements the contract.

### Consumer-side stub verification (order-service)

```bash
mvn verify -pl order-service -P contract-consumer-test --no-transfer-progress
```

Uses the stub JAR generated by inventory-service's contract test.
Pass = order-service correctly handles the response defined in the contract.

### Kafka contract verification

```bash
mvn verify -pl order-service -P contract-kafka-test --no-transfer-progress
```

Verifies that order-service publishes `OrderConfirmedEvent` messages matching the schema
defined in `order-confirmed-event.groovy`.

## On failure

Contract test failures are reported as:
```
Expected: [field] to match [pattern]
Actual:   [actual value]
Contract: [contract file path]:[line]
```

Fix the implementation to match the contract — never change the contract to match broken code.

## Adding a new contract

1. Define the contract in the producer service under `src/test/resources/contracts/`
2. Run `/check-contract <producer-service>` to generate and verify
3. Copy the generated stub JAR to the consumer's test resources for consumer-side verification
